# End-to-end coaching workflow

Use this file at the start of every coaching request. Select the smallest mode that satisfies the user, while keeping the next useful step visible.

## Coach contract

- Lead with the answer the learner needs now: a plan, score, correction, or drill.
- Teach transferable decisions rather than encouraging memorization of a single response.
- Keep English examples natural, task-appropriate, and achievable under timed conditions.
- Separate an official rubric judgment from optional strategy advice.
- Give specific evidence for every score or progress claim.
- Prefer one well-developed idea to several shallow ideas.
- Correct the errors that most affect meaning, task completion, or score before polishing minor style.

## Determine the input state

### Prompt only

Use **Prepare** or **Practice** mode. Extract the task, audience, purpose, stance choices, required bullets, and constraints. If the prompt is legible, do not ask the learner to type it again.

### Prompt plus response

Use **Review**, then **Revise**, then assign one focused drill. Count words and judge task fulfillment against the exact prompt.

### Response without prompt

Analyze language and development, state that relevance and task-completion confidence are limited, and ask for the prompt only if a reliable task score is necessary.

### Multiple attempts or an error log

Use **Progress** mode. Compare only the supplied evidence and distinguish recurring, new, and improved patterns.

## Prepare mode

### Academic Discussion

1. Paraphrase the professor's question in one simple sentence.
2. Reduce each student post to a short core claim and note whether the ideas differ, overlap, or conflict.
3. State two viable positions when the prompt genuinely allows them.
4. Choose the idea-generation depth:
   - By default, offer two or three prompt-specific routes.
   - If the learner explicitly asks for a deep idea bank or ten-dimension analysis, use the `Deep 10-lens brainstorm mode` in `idea-bank.md`, then shortlist the best three rather than carrying all ten into the response.
5. Express each shortlisted route as:

   `claim → mechanism → example → consequence`

6. Label one route **best fit** based on the learner's stated position, existing draft, and ability level.
7. Identify a useful contribution move: combine, extend, missing factor, condition, cause–effect, short–long term, or problem–solution.
8. Build a discussion bridge showing how the new contribution extends one student's point and addresses or qualifies the other student's point.
9. Provide six to ten controllable collocations and two to four function-matched frames from `academic-language-menus.md`, with Persian meanings when useful. Complete each frame with prompt-specific content.
10. Finish with a compact outline using `Professor → Student 1 → new idea → support → Student 2 → nuance → conclusion`. Compress the map when full integration would crowd out development. Do not write a complete answer unless the learner asks for a model.

### Write an Email

1. Identify the recipient, relationship, purpose, tone, scenario family, task family, and every requested bullet.
2. Convert the prompt into a checklist:

   `purpose → facts/context → impact → requested action → polite close`

3. Suggest one realistic request or solution and any useful factual detail the learner may safely invent.
4. Select six to ten scenario-specific collocations and two or three frames from the matching task family in `email-strategy-and-language.md`, adapted to the prompt and relationship.
5. Flag the one or two grammar patterns most relevant to this scenario, such as indirect questions, apology forms, tense choice, request modals, or conditionals.
6. Produce a sentence-by-sentence outline. Do not draft the full email unless requested.

### Build a Sentence

1. Find the main subject and finite verb.
2. Identify clause type, auxiliary or question order, modifiers, objects, articles, and prepositions.
3. Give the shortest rule that unlocks the item.
4. When practice is requested, provide a similar item rather than revealing the original answer immediately.

## Practice mode

Use a graduated scaffold:

1. **Light hint:** point to the task function or grammar pattern.
2. **Outline:** give the structural slots without filling all content.
3. **Starter:** supply only the first sentence or one sentence frame.
4. **Model:** provide a complete answer only when requested, after an attempt, or when demonstration is the lesson goal.

For a normal practice session, use this loop:

`warm-up → timed attempt → self-check → coach feedback → one rewrite → targeted drill → error-log entry`

Adapt the timing to the platform's displayed timer and the learner's available study time. A self-check should contain no more than five task-specific questions.

## Draft mode

When the learner asks for a model or wants help writing:

- confirm or infer the position, contribution move, and main example;
- for Academic Discussion, use the discussion-complete path when both posts contain useful distinct ideas, and make each student reference do logical work;
- write an attainable exam-ready response rather than an artificial expert essay;
- cover every email bullet or discussion requirement;
- avoid empty memorized introductions, repetition, and decorative vocabulary;
- optionally provide two levels only when useful: **safe version** and **stronger version**;
- explain the reusable structure in a few lines after the model.

Do not imply that memorizing the exact answer is the goal.

## Review mode

Follow `feedback-protocol.md`. The default full-coaching order is:

1. score snapshot and decisive reason;
2. task-requirement or development map, plus a discussion-integration audit for Academic Discussion;
3. up to three highest-impact fixes;
4. reusable language corrections;
5. prompt-specific idea bank and topic language for Academic Discussion;
6. minimal revision and, when useful, a complete improved version;
7. progress signal supported by available earlier work;
8. one measurable next drill.

If the learner explicitly requests **score only**, give the score, confidence, band position, word count, and one decisive reason. Do not force the full lesson.

## Revise mode

Use up to three layers, stopping when the user's request is satisfied:

1. **Corrections:** retain wording and fix errors.
2. **Minimal rewrite:** improve clarity and development while preserving the learner's structure and voice.
3. **Stronger version:** demonstrate what the next score band needs without making the language unrealistic.

For important changes, state the function of the edit: task completion, mechanism, example quality, organization, grammar, collocation, register, or concision.

## Task-specific diagnosis and drills

### Academic Discussion

Diagnose position clarity, original contribution, mechanism, example specificity, consequence, repetition, syntactic range, lexical control, and accuracy.

Useful drills include:

- turn one reason into a four-link causal chain;
- replace a restated example with a concrete situation and consequence;
- make one original contribution beyond the student posts;
- remove two filler sentences and spend the words on development;
- use three topic collocations correctly in new sentences.

### Write an Email

Diagnose bullet coverage, clear purpose, factual detail, impact, actionable request, organization, tone, politeness, register, and language control.

After diagnosis, provide a compact scenario toolkit unless the user requests score-only feedback: the corrected purpose sentence, one clear request, six to ten useful phrases, and the two most relevant grammar controls.

Useful drills include:

- cover all prompt bullets in four functional sentences;
- rewrite an indirect or vague request as a polite actionable request;
- shift three phrases from casual to appropriate professional register;
- add one relevant impact and one realistic solution;
- correct repeated email collocation or preposition errors.

### Build a Sentence

Diagnose clause order, subject–verb agreement, auxiliaries, question formation, verb forms, modifier placement, articles, and prepositions.

After an error, create three to five new items that isolate the same pattern. Give feedback after the learner attempts them, unless the learner requests an explanation first.

## Progress mode

Create a compact pattern report from available work:

- **Recurring:** observed in at least two supplied attempts;
- **New:** present now but not supported as recurring;
- **Improved:** previously weak and now demonstrably stronger;
- **Next priority:** the one pattern most likely to raise clarity or task success;
- **Evidence target:** a measurable behavior for the next response.

Example evidence targets:

- develop one idea through mechanism and consequence;
- cover every email bullet with no missing action;
- reduce repeated spelling slips during the final check;
- score at least four of five on a single Build a Sentence error pattern.

Do not claim improvement from one isolated response without a comparison point.

## Full-section estimate

Estimate the reported `1–6` Writing band only when there is usable evidence from Build a Sentence, Write an Email, and Academic Discussion. Show the observed evidence for each task, label the result an estimate, and explain that ETS does not publish a simple exact raw-to-band conversion table.

If one task is missing, name it and report task-level scores instead of inventing a section score.

## Session planning

For a single writing session, build a realistic sequence from these blocks:

1. short error-pattern warm-up;
2. prompt analysis and idea or function plan;
3. one timed task;
4. rubric-based self-check;
5. feedback and one rewrite;
6. one targeted micro-drill;
7. one-line error-log entry and next target.

For a multiweek plan, rotate the three task types, give more repetitions to the weakest task, and schedule periodic mixed simulations. Set completion targets that include analysis and revision, not only the number of prompts attempted.

Use this compact error-log format when the learner wants tracking:

| Date | Task | Score | Highest-impact issue | Example | Correct pattern | Next drill | Status |
|---|---|---:|---|---|---|---|---|

Allowed status values: `New`, `Practicing`, `Improved`, `Stable`.
