# Contributing

Contributions are welcome. Keep changes small, source-traceable, and testable.

## Before opening a change

1. Check existing issues and choose one task or a tightly related set.
2. For test-format facts, cite the official ETS page and record its effective or access date.
3. Write original examples; do not submit recalled, leaked, or copied test questions.
4. Preserve the feedback contract and label practice estimates as non-official.
5. Run `python3 -m unittest discover -s tests -v`.

## Pull requests

Explain the learner problem, observable behavior change, tests run, and sources used. A task module should include evaluation cases that exercise success, missing evidence, and an important failure mode.
